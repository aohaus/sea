# 面談前ブリーフ

日系企業向けコンサルティングの責任者が、経営層との面談の前に5分で読む1ページを作る。

## 手順

1. 会社名を確かめる。`config/signals_watchlist.json` にあれば、その `name` で `signals/data/signals.json` の
   `items` を絞り、直近120日の記事を新しい順に読む。なければ `title_ja`・`title`・`summary_ja` を社名で検索する。
2. 国の前提は `basic/my/indicators.json`、`basic/my/profile.json`、`basic/ties/`（日本からの直接投資、在留邦人、
   訪問者）から、その会社の話題に関わる数字だけを取る。
3. ウェブ検索が使えるなら、その会社のマレーシア拠点（所在地、事業、従業員規模、最近の発表）と日本本社の
   中期経営計画・直近決算の要点を確かめる。使えないなら、その旨と、確かめられなかった項目を書く。
4. 下の型で書く。事実には出典（媒体名と日付、または URL）を付ける。推測は「仮説」と明記する。

## 型（A4 1枚、日本語）

- **この会社のいま**（3行）：マレーシア拠点の役割、規模、直近の動き
- **直近のシグナル**（最大5件）：日付・媒体・何が起きたか・なぜ面談で使えるか
- **課題の仮説**（3つ）：それぞれ「根拠となる事実 → 経営課題 → 最初に小さく始められる支援」の順
- **聞く質問**（5つ）：答えが案件の有無を分ける質問。はい／いいえで終わらないもの
- **持っていく一言**：相手がまだ知らなさそうな、数字のある事実を1つ
- **避けること**：独立性・利益相反の確認が済んでいない支援の提案、報道だけを根拠にした断定

## きまり

- このリポジトリは公開。ブリーフ、面談メモ、目標、ターゲットの優先度はリポジトリに書かず、会話に出すか、
  ユーザーが指定した非公開の場所（非公開の Artifact、Drive）に置く。
- 監査先かどうかで提供できる支援が変わる。ユーザーが確認済みと言わない限り、ブリーフの冒頭に
  「独立性・利益相反の確認：未」と書く。
- 要約は自動翻訳を含む。固有名詞と金額は元記事で確かめ、確かめられないものは「未確認」とする。
